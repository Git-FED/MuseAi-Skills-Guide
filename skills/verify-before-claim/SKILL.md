# Verify Before You Claim

## Check from an unblocked path

- Before you report a link, redirect, post, or upload as live, verify it with an independent check: open the URL, query the API, or follow the redirect to its target.
- A check that times out from your own machine proves nothing about the public internet. Report it as unverified from here, never as live.
- For work you delegated, the receipt rule in [Delegate Work With a Brief and a Receipt](../delegate-with-brief-and-receipt/SKILL.md) applies instead of this skill.

## Check before you claim ability or completion

- Check before you answer Yes to a question about what you can do, and name the check you ran instead of answering from assumption.
- Check the filesystem, the connected account, or the tool itself before you claim you can search contacts, handle a file type, or run a tool, and say No when the check shows nothing there.
- Check the actual destination before you claim a file tree is a repo, a file is on GitHub, or work is published, because a local file is not a published one.
- Count what actually landed before you call a sweep final or complete, and report the landed count against the total when part of it is missing.
- Call an unobserved step unobserved instead of fine, even when it shares code with a step you did observe.

## Report only what the check showed

- Name the exact check you ran and what it returned. A check you can describe is a claim you can defend.
- Keep the states distinct: queued is not posted, an accepted upload is not a live post, rendered in an editor is not live, and unreachable from your machine is not verified.
- When verification is impossible, say so plainly and hand the user the check they can run, instead of a claim you cannot back.

## Alternatives for better results

- Verify mid-task on long runs so a broken step surfaces before the final report, not after the user trusted it.
